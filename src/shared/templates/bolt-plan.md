# Bolt Plan Template

> XML-structured execution plan for a single bolt within a unit.
> Each bolt targets completion in hours, not days.
> Lives at: `.aidlc/construction/unit-NNN/bolt-NNN-plan.md`

## Instructions for agents

- Generated by `sdlc-bolt-planner` during `__CMD_PREFIX__plan-unit`
- Each task must trace to a unit acceptance criterion
- Tasks must be atomic — completable in fresh context
- Verification step per task (proof over prose)
- Must check that inception gate is passed before planning

<guidelines>

**Task granularity:**
- Each task = one atomic commit
- Task should be completable without referencing other tasks
- Include enough context that a fresh agent can execute it
- 3-7 tasks per bolt is typical

**XML structure:**
- `<task>` wraps each task with id, name, and dependencies
- `<verify>` inside each task — MUST be present (proof over prose)
- `<done>` wraps completion criteria — checked after all tasks
- `depends_on` attribute enables parallel execution within a bolt

**Frontmatter fields:**
- `wave` — for parallel execution across bolts (wave 1 runs before wave 2)
- `depends_on` — bolt-level dependencies (not task-level)
- `files_modified` — enables file ownership checking across parallel bolts
- `autonomous` — whether this bolt can run without human checkpoints
- `must_haves` — observable truths that the verifier checks after execution

**Ralph Loop:**
If verification fails after bolt execution:
1. Analyze what failed
2. Create a fix bolt (bolt-NNN+1-plan.md)
3. Execute fix bolt
4. Re-verify
5. Loop until all must-haves pass

**Gate check:**
Refuse to create bolt plans if inception gate has not passed.
Read `state.md` or `audit.md` to verify.

</guidelines>
